# cf808097: durable delivery follow-up

Development only: no production deployment, service restart or commit.
Never copy production runtime/config/store data into tests.

## Scheduled identity
Use the original cron occurrence, not the attempt time. Retry rows persist
scheduled_occurrence; task_runs record it in the delivery transaction.
UNIQUE(task_id, scheduled_occurrence) independently prevents duplicate deliveries.
Existing retries without an occurrence require manual review; never infer it
from first_attempt. Manual requests use their request timestamp.

Only queued work can be claimed. Claim commits before model/tool execution.
Restart changes running to interrupted; failed/interrupted work cannot replay.
Assumption: one scheduler and one channel host. Recovery is conservative,
not a distributed lease protocol. Never launch another production host for tests.

## Legacy queue
Unversioned pending does not prove that execution never started. Such records
become interrupted/manual_review. Only a trusted outer queueVersion=2,
status=queued, attemptCount=0, startedAt=null marker proves an unstarted item.
Malformed entries also require review; message content cannot supply proof.
Destination journal commits before JSON queue removal. Stable ids make migration
repeatable if JSON persistence fails. New intake goes directly to the journal.

## Notifications
Stable notificationId; pending -> sending -> sent | failed | manual_review.
Only confirmed provider acknowledgement permits sent/notified_at. A restart
during sending or an uncertain transport failure requires manual review, never
automatic resend. Old pre-send notified_at stamps are unconfirmed too.
Unconfirmed states persist in SQLite and are logged at startup/on send errors.
Absolute exactly-once external delivery cannot be guaranteed: acceptance followed
by a crash before local acknowledgement is indistinguishable from an unsent call.
This policy avoids blind duplicates, at the cost of requiring manual decisions.

## Test safety
Synthetic stdin/stdout fixture only; no network or real account.
--offline-import-smoke only loads imports. For --bridge-test explicitly select
the synthetic fixture as MARVEEN_CODEX_BIN, inside an isolated sandbox.
Use source-only snapshots, fresh temporary databases, synthetic HOME/config,
separate process/network/mount namespaces and read-only dependency packages.

The release comparison has two explicit source states:

- A = clean Git HEAD + `00-codex-base.patch`;
- B = A + `01-cf808097.patch`.

Run both with the same dependencies, synthetic home and fresh temporary test
state. B may add tests, but no test that passes in A may fail in B. Targeted
lifecycle tests, typecheck and build must all pass before production approval.

Codex channel recovery is pane-scoped. `hardRestartMarveenChannels()` must use
`tmux respawn-pane` with `codex-channels.sh --pane`; it must never restart the
systemd channels unit, because that unit may share a tmux server with unrelated
agents.

## Rollback plan ? NOT EXECUTED
Stop approved writers gracefully, preserve all new journals, then restore prior
code/build only after compatibility review. Do NOT blindly restore old queue
JSON or a stale database: this can repeat actions or erase newly accepted work.
If no work was accepted since backup, an operator may approve consistent full
state restoration. Otherwise keep services paused for explicit reconciliation.
Old code cannot read the new channel journal and may blindly replay old pending
records; rollback is therefore not an automatic file-copy/restart procedure.
The rollback decision must also preserve the pane-scoped channel recovery fix;
reintroducing the old systemd restart branch can terminate unrelated sessions.
